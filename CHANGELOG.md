# Changelog

The version scheme follows the other IFDD templates: `YY.MM.N`.

## [26.10.2] - 2026-10-14

- Documentation of the instance in `docs/en` and `docs/de` (Sphinx sources,
  MyST Markdown): index, setup, build and release, operations, security,
  troubleshooting, reference, login gate. The pages show only what the chosen
  options produce. The instance README is now an entry point with a quick
  start, the links, the honesty notes and the license; its former sections
  moved into the documentation.
- `docs/_build/` in `.gitignore` of the instance.
- Template CI: `tests/check_docs.py` checks that both languages match and
  build without warnings (`tests/docs/conf.py`, `tests/docs/requirements.txt`),
  in both jobs.
- `ifdd_proxy_csp_api_docs`: default without CDN, Google Fonts and
  `fastapi.tiangolo.com` (ifdd-be-core now serves Swagger UI and ReDoc
  itself, without inline scripts) and with `worker-src 'self' blob:` for
  ReDoc's search. `connect-src` must name the realm origin for "Authorize";
  the default cannot know it, `cookiecutter_all.yaml` sets it. Comment in
  `headers.yml` and the instance README updated. Existing instances get the
  value with `cruft update --variables-to-update`.

- README, security headers: `csp-ui` must also allow the type and unit
  services in `connect-src` (the UI reads vocabularies and units there). The
  values come from `cookiecutter_all.yaml`; the template default of
  `ifdd_proxy_csp_ui` is unchanged.
- `ifdd_proxy_oauth2_proxy_ca_file` (default empty): CA certificate in
  `certs/` that oauth2-proxy trusts when it calls the realm, for realms behind
  certificates of a local CA (`adm_01_certs.sh`). Only that file is mounted,
  read-only and with `create_host_path: false`; `OAUTH2_PROXY_PROVIDER_CA_FILES`
  and `OAUTH2_PROXY_USE_SYSTEM_TRUST_STORE=true` are set in the compose file.
  The pre-generation hook rejects a value with a path.
- Instance README, oauth2-proxy: users need an e-mail address marked as
  verified; steps to enable oauth2-proxy in an existing instance.
- Tests: `tests/check_oauth2_proxy.py`, two instance tests, fixture
  `oauth2-proxy-public-ca`; CI renders and checks both oauth2-proxy fixtures
  (no smoke test: without a reachable realm oauth2-proxy does not start).
- Dashboard login out of the box: `ifdd_proxy_dashboard_user` (default
  `admin`); the post-generation hook generates a password (32 letters and
  digits) into `.env` (`IFDD_PROXY_DASHBOARD_USER`,
  `IFDD_PROXY_DASHBOARD_PASSWORD`, `.env` now mode 0600) and writes the
  matching APR1 line to `secrets/dashboard.htpasswd`; an existing file is
  kept. The pre-generation hook rejects user names with characters other
  than letters, digits, `_`, `.`, `@`, `-`. Existing instances are not
  touched (`secrets` is on the skip list); see `secrets/README.md`.
- oauth2-proxy: health check (`wget` on `/ready`); default image now
  `quay.io/oauth2-proxy/oauth2-proxy:v7.15.5-alpine`, because the default
  images are distroless and have no `wget`. The pre-generation hook refuses
  an image without `-alpine` when oauth2-proxy is enabled. Upgrade: instances
  with oauth2-proxy need `--variables-to-update` with the new image (instance
  README, "Enabling it in an existing instance").
- Tests: `tests/check_dashboard_credentials.py` (hash checked with openssl);
  the smoke test logs in with the generated credentials; the fixture
  `internal-hosts` sets a user name.

- Optional oauth2-proxy (`ifdd_proxy_enable_oauth2_proxy`, default `n`):
  shared OIDC login gate against Keycloak for services behind the proxy;
  the Keycloak group is chosen per service with `allowed_groups` in its
  forward-auth address. Cookie secret generated by the post-generation hook,
  client secret in `secrets/`. With the default `n` an instance renders
  exactly as with 26.10.1.

## [26.10.1]

Initial release.

- Traefik v3.7.13 as upstream image, configured from one rendered static file
  (`traefik/traefik.yml`, `traefik/traefik.development.yml`); no CLI flags
  besides `--configFile`, nothing from `.env` inside the container.
- TLS with own certificates or Let's Encrypt (HTTP-01, resolver set on the
  `websecure` entry point), TLS 1.3 minimum by default, `sniStrict`,
  `core.strictTLSOptions`.
- Dashboard only via `/dashboard` and `/api` behind basic authentication,
  `api.insecure` off, health check on a loopback-only ping entry point.
- Optional read-only Docker socket proxy.
- DoS baseline (rate limit and in-flight limit per source) on the entry point,
  body-size buffering as opt-in middleware per router.
- `aliasHeadersStrategy` on every entry point.
- Development compose file with Traefik's self-signed default certificate.
- Static checks and a Docker smoke test in every instance; template render,
  check and smoke test over three fixtures; cruft update test.
